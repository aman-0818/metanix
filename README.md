# Matenix AI

A responsive enterprise website based on the supplied company profile: practical AI products, system integration, custom automation, and enterprise AI governance.

## Run locally

Requires Node.js 20.9 or later. In Windows PowerShell:

```powershell
npm.cmd ci
Copy-Item .env.example .env.local
npm.cmd run dev
```

Open [http://127.0.0.1:3000](http://127.0.0.1:3000). On macOS/Linux, use `npm` in place of `npm.cmd` and copy `.env.example` to `.env.local` using your shell or editor.

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run build
npm.cmd run start
```

`dev` starts the development server. `build` generates the production application; `start` serves that build locally.

## Stack and structure

Next.js 16 App Router, React 19, TypeScript, Tailwind CSS v4 with CSS tokens, Framer Motion, and Lucide outline icons. Latin subsets of Geist and Geist Mono are self-hosted through `next/font/local`; no external font CDN is used. Font licences are included in `public/font-licenses`. Motion respects reduced-motion preferences and animation code loads after interaction.

| Location | Purpose |
| --- | --- |
| `src/content/site.ts` | Typed company, product, industry, navigation, and editorial content; ready to map to a future CMS |
| `src/app` | Shared layout, homepage, statically generated marketing/product routes, contact API, and SEO endpoints |
| `src/components/ui.tsx` | Shared buttons, badges, cards, headings, and accessible form fields |
| `src/components` | Navigation, footer, interactive product concepts, consultation intake, and scoped page styles |
| `src/app/globals.css` | Color, type, spacing, layout, focus, and motion tokens |
| `src/lib` | Shared contact validation and metadata helpers |
| `tests/site.spec.ts` | Playwright browser, API, responsive, and automated accessibility checks |

The 16 public routes are `/`, `/solutions`, `/products`, `/products/m-vcara`, `/products/m-resora`, `/products/m-ordena`, `/industries`, `/system-integration`, `/ai-automation`, `/enterprise-ai-governance`, `/company`, `/contact`, `/resources`, `/insights`, `/privacy`, and `/terms`.

`/design-system` is an additional visual component reference excluded from search indexing. Sitemap, robots, Open Graph artwork, and page metadata are generated by the app.

The supplied purple/cyan logo is preserved at `public/brand/matenix-logo.png`. Shared branding, architecture diagrams, browser and Apple touch icons, and the social preview all use this artwork. `LogoMark` frames its transparent margins without changing the source image; Next.js optimises its delivery at each display size.

## Contact demonstration and content

The consultation form validates in the browser and posts to `/api/contact` for server validation. This is an explicit demonstration: the application handler does not send enquiries to a CRM or email provider, store submissions, or log their contents. A successful response reports `demo: true` and `sent: false`. Use sample information while trying it. Hosting infrastructure may have its own request logging.

Company and product copy follows the supplied sources. Product diagrams are labelled illustrative concepts. The site does not invent customers, metrics, certifications, or unprovided product capabilities. Privacy and terms are clearly marked drafts and excluded from indexing; legal entity details, approved policies, and effective dates remain company inputs.

See [the design system](docs/design-system.md) for tokens and component APIs, [content notes](docs/content-notes.md) for source boundaries, and [verification results](docs/verification.md) for browser checks and measured performance.

## Browser tests

Build first; Playwright starts the production server automatically or reuses a server already running on port 3000:

```powershell
npm.cmd run build
npm.cmd run test:e2e
```

On Windows, the configuration automatically uses Chrome when installed at `C:/Program Files/Google/Chrome/Application/chrome.exe`. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to another browser executable if needed. Otherwise, install Playwright Chromium with `npx.cmd playwright install chromium` (`npx playwright install chromium` on macOS/Linux).

Tests cover page responses and metadata, internal links, required viewport widths, keyboard interactions, mobile navigation, contact validation, and automated accessibility. HTML reports are written to `playwright-report`; failure traces and screenshots go to `test-results`. Test output is the source of verification results; no performance score is assumed.

With the production server running, `node scripts/capture-preview.mjs` saves desktop/mobile screenshots. `node scripts/audit-performance.mjs` runs three mobile Lighthouse trials per key page and saves reports plus median scores in `artifacts/`. Local preview indexing is disabled until a public origin is configured, which reduces the local SEO score.

## Deployment

The project uses the standard Vercel Next.js preset and is ready to deploy after the actual site configuration is supplied. Set `NEXT_PUBLIC_SITE_URL` to the verified HTTPS origin before building; it controls canonical metadata, social URLs, structured data, and sitemap URLs. The local fallback is `http://localhost:3000`.

For a live enquiry service, connect `/api/contact` to the chosen delivery provider or CRM and align the form confirmation and privacy copy with its real handling. Supply the approved legal entity/contact details, policies, and dates before publishing the legal pages as final. Add product specifications, integration lists, or customer evidence only when provided and verified by the company.
